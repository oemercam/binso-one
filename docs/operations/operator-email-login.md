# Operator sign-in with email codes

Deploy the additive migration and application with both flags disabled. To prepare existing operators, enable only `BINSO_OPERATOR_EMAIL_SETUP`. The setup link does not require Entra authentication. Run `node scripts/provision-operator-email-link.mjs <existing-operator-email>` through the approved private database administration path. Verify the recipient and deliver the resulting one-time link privately. The link expires after 30 minutes and must be kept out of logs and tickets.

Verify that an active owner and the required operators can set their own passwords under the [shared password policy](../password-policy.md). Confirm the existing mail-provider configuration before the cutover. Then enable `BINSO_OPERATOR_EMAIL_LOGIN` and immediately verify real code delivery, sign-in and role checks with a prepared owner. If any check fails, turn off the login flag and verify the previous sign-in mode. The dedicated code expires after ten minutes and is bound to the originating browser. A new code requires password proof again.

The local session uses the current database assignment. While this mode is enabled, Entra group changes do not update assignments automatically. Suspend the database assignment during offboarding. When recovering a password, issue a fresh setup link through the same verified channel. Setting a replacement password invalidates existing email-code sessions for that operator. To restore the previous sign-in mode, turn off the email-login flag and verify the Entra login. Do not disable the Azure identity provider as part of the change.
